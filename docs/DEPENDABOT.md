# Dependabot → Devin → independent evidence → human merge

Dependabot creates an update PR in `Nasdin/superset`, targeting `cognition-release-6.1`. The signed GitHub `pull_request` webhook accepts `opened`, `reopened`, `ready_for_review`, and `synchronize`. Before enqueueing, the service fetches the PR from GitHub and checks the real author is `dependabot[bot]` with type `Bot`, both repositories are the configured fork, the base branch is the configured release branch, and the PR is open and not a draft. An event for an old SHA is ignored.

The worker also polls open PRs once a minute as recovery for missed events. It rotates through pages of 100. Intake deduplicates by repository, PR and head SHA; repeated delivery IDs are recorded. Events generated by the implementation's own pushes coalesce into its existing job. Reopening or returning to a previously stale SHA creates a fresh validation generation instead of reviving old evidence.

## Execution and evidence

1. Recheck the live PR immediately before starting a paid session. Reserve capacity for preparation plus independent validation under the existing total-session cap.
2. Devin reads the update/release notes, installs dependencies, runs relevant checks, and repairs compatibility issues **on the existing Dependabot branch**. It must not create a replacement PR, merge, weaken tests or CI, or modify an unrelated branch.
3. Its final handoff must name the original PR URL, unchanged head branch, and current full SHA. Missing, conflicting or blocked results require attention.
4. A **fresh Devin session** checks out that SHA and starts Superset from the actual code. It checks services, database behavior, the browser journey, and regression tests. It records screenshots, video, service logs and test outputs as provider attachments.
5. The gate verifies session independence, exact SHA, required passing checks, distinct provider-confirmed attachment IDs/URLs and appropriate media types. Failures stay visible; they are not presented as approval.
6. A durable outbox publishes the report on that same PR and, when configured, in Slack. Acknowledged writes store their receipt before confirmation; a failed readback retries confirmation, not posting. An ambiguous mutation is held for reconciliation.
7. The engineer reviews the PR and evidence and merges manually. This system has no automatic merge step for Dependabot or release PRs.

Changed head, closure, or retargeting invalidates review-ready evidence. Eligible new heads receive new validation. Periodic freshness checks run once a minute; the UI is an observed ledger, not a GitHub branch protection rule. The report names its exact SHA so a reviewer can compare it with the current PR. GitHub comments are historical evidence, not a live approval badge.

## Pages and classifications

**Dependabot runs** shows only bot-authored PRs in the workflow fork. **PR evidence** shows the fork's dependency/fix/feature/other PRs and groups preparation, validation, artifacts and publication receipts under the original PR. Both pages support filters and pagination. Cached GitHub metadata shows its last successful synchronization time; workflow records refresh every five seconds.

**Analytics** can separately inspect `apache/superset` or the fork. Change type is a retrospective title/label signal, not a semantic code review. Bot identity is a separate author attribute. Feature analytics are descriptive; feature PRs are not automatically assigned to Devin by this feature.
